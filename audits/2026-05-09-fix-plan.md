## Architectural Decisions (set by user 2026-05-09)

1. **ECDSA and BLS families: implement for real, mirror POA's surface.**
   Operator self-registration with owner-managed weights, single-contract stake-registry-style (matching `poa-middleware/contracts/src/{ecdsa,bls}/POAStakeRegistry.sol`). These serve standalone Cosmos AVSs that don't need an EVM anchor.

2. **Mirror family: keep.** It serves the bridging use case — an EVM-side operator set bridged to a CosmWasm chain (e.g. Juno) via signed envelopes. Both ECDSA-mirror and BLS-mirror variants in scope long term; only ECDSA-mirror exists today and stays the supported mirror flavor for this round.

3. **Mock family: delete entirely.** With real ECDSA and BLS implementations, the mock family is dead weight and a source of footguns (C-4, M-3). Tests that need a fake service-manager build one inline.

4. **C-5 fix shape: both.**
   - Sync handlers instantiate their downstream contracts with handler-as-owner during deploy (canonical path).
   - Stake-registry / service-manager also expose `TransferOwnership` / `SetAdmin` for emergency rotation. This addresses H-6 simultaneously.

5. **BLS feasibility:** confirmed. CosmWasm 3.x exposes `bls12_381_pairing_equality`, `bls12_381_aggregate_g1`, `bls12_381_aggregate_g2`, and `bls12_381_hash_to_g2`. The repo already pins `cosmwasm-crypto` from the matching upstream. Target chains must run CosmWasm ≥ 2.1 (Juno post-v25, Neutron, Osmosis, etc.).

## Phase 2 — ECDSA family: real implementation (C-1, C-3, H-6, M-5, L-1, L-2)

POA-shape: a single per-family stake-registry-style contract (folded into `service-manager`) that holds operator state, signing keys, weights, quorum, and signature validation. Mirrors `poa-middleware/contracts/src/ecdsa/POAStakeRegistry.sol` semantics; uses CosmWasm idioms.

### State (cw-storage-plus)

```rust
pub const OWNER: Item<Addr>                                    // C-3, H-6
pub const PENDING_OWNER: Item<Addr>                            // two-step transfer
pub const QUORUM_NUMERATOR: SnapshotItem<Uint256>              // M-4 alignment
pub const QUORUM_DENOMINATOR: SnapshotItem<Uint256>
pub const SERVICE_URI: Item<String>                            // gated
pub const TOTAL_WEIGHT: SnapshotItem<Uint256>
pub const OPERATOR_WEIGHTS: SnapshotMap<Addr, Uint256>
pub const OPERATOR_TO_SIGNING_KEY: SnapshotMap<Addr, Addr>     // operator -> secp256k1 pubkey-derived addr
pub const SIGNING_KEY_TO_OPERATOR: SnapshotMap<Addr, Addr>     // reverse index, snapshotted
pub const OPERATOR_REGISTERED: Map<Addr, bool>
```

### Execute messages

| Message | Caller | Purpose |
|---|---|---|
| `RegisterOperator { signing_key, weight }` | OWNER | Mirrors POA `_registerOperator`. Snapshots weight + signing key. |
| `DeregisterOperator { operator }` | OWNER | Decrement total weight; clear maps at current height (snapshot retains history). |
| `UpdateOperatorWeight { operator, weight }` | OWNER | Change weight; recompute total via `checked_sub`/`checked_add`. |
| `UpdateOperatorSigningKey { new_signing_key }` | operator (self) | Snapshot the new key; validate length + uniqueness. |
| `WavsSetQuorumThreshold { numerator, denominator }` | OWNER | C-3 fix. SnapshotItem write. |
| `WavsSetServiceUri { service_uri }` | OWNER | C-3 fix. |
| `TransferOwnership { new_owner }` | OWNER | Two-step (set pending). H-6 fix. |
| `AcceptOwnership {}` | PENDING_OWNER | Two-step completion. |

### Query messages

`WavsValidate { envelope, signature_data }` — port `mirror/stake-registry::is_valid_signature` directly:

1. Reject empty signers list, enforce `signers.len() == signatures.len()`.
2. Validate signers are sorted (replay-resistance against permutation tricks; matches POA `_validateSortedSigners`).
3. For each `(signer_addr, sig)`:
   - `keccak256(envelope.as_slice())` → `eip191_hash_message(...)` → digest.
   - `secp256k1_recover_pubkey(digest, sig.r||s, sig.v)` → recovered pubkey.
   - Derive Ethereum-style address (`keccak256(pubkey[1..])[12..]`).
   - Compare against `signer_addr`; reject on mismatch.
   - Look up operator: `SIGNING_KEY_TO_OPERATOR.may_load_at_height(reference_block)` only — **no fallback to latest** (avoids the H-2 bug class for new code).
   - Look up weight: `OPERATOR_WEIGHTS.may_load_at_height(reference_block)` — same rule.
   - Accumulate signed weight.
4. Read total + threshold at `reference_block` (SnapshotItem reads).
5. Verify quorum via `Uint512` math: `signed * denominator >= total * numerator`.

Other queries: `WavsQuorumThreshold`, `WavsOperatorWeight { reference_block? }`, `WavsServiceUri`, `WavsLatestOperatorForSigningKey`, `WavsTotalWeight { reference_block? }`, `WavsOperatorRegistered`, `Owner`.

### M-5 fix (untagged enum)

`api/src/service_manager.rs` currently has `#[serde(untagged)]` on `ExecuteMsg::Wavs`. Replace with explicit tag (`#[serde(rename_all = "snake_case")]`) or fold the `Wavs` wrapper into the top-level enum so the discriminant is unambiguous.

## Phase 3 — BLS family: real implementation (C-1, C-2, C-3, H-6, M-5, L-1, L-2)

Same shape as ECDSA (Phase 2). The only differences:

1. **Signing key type**: BLS12-381 G1 compressed pubkey (48 bytes) per POA `bls/POAStakeRegistry.sol`.
2. **Verification path**: aggregate signatures and pairing equality.

### Verification (port from POA `BLS12381.sol`)

```text
APK    = bls12_381_aggregate_g1(signers' G1 pubkeys)
H_msg  = bls12_381_hash_to_g2(envelope_digest, DST = "BLS_SIG_BN254G1_XMD:..." or BLS12381 standard DST)
sig    = aggregated G2 signature

bls12_381_pairing_equality(G1::generator, sig, APK_neg, H_msg) == true
```

cosmwasm-crypto host calls used:
- `bls12_381_aggregate_g1` — combine signer pubkeys into APK.
- `bls12_381_hash_to_g2` — hash envelope digest to G2 (DST must match POA's DST byte-for-byte).
- `bls12_381_pairing_equality` — equality of products of pairings.

### Key registration

Operator registers with their G1 pubkey. Snapshot map keys: `Addr → Vec<u8>` (48 bytes G1 compressed). Validation rejects malformed pubkeys via host-call return code on first use; ideally also pre-validate at registration time by aggregating against a single point.

**H-2 details** (`mirror/stake-registry/src/entry.rs:288-300, 311-324`):

```rust
// Before
let operator = match SIGNING_KEY_TO_OPERATOR.may_load_at_height(...)? {
    Some(op) => op,
    None => match SIGNING_KEY_TO_OPERATOR.may_load(...)? { Some(op) => op, None => err }
};

// After
let operator = SIGNING_KEY_TO_OPERATOR
    .may_load_at_height(deps.storage, signing_key_str.clone(), reference_block)?
    .ok_or_else(|| StdError::msg("Signer not registered at reference block"))?;
```

Same shape for `OPERATOR_WEIGHTS`. Add an explicit regression test (Phase 7).

**H-5 details**: pick `MAX_GAP` such that legitimate event streams stay under it but `u64::MAX` cannot brick the contract. Suggest `MAX_GAP = 2^48` (≈ 280 trillion events; rejects sentinels but never fires on real workloads).

## Phase 5 — Mirror C-5: fix the deploy-flow ownership gap (C-5, H-6)

This is the structural fix. Two sub-changes:

### 5a — Sync handlers instantiate their downstream contracts with self-as-owner

**Operator-sync path:**
- `mirror-operator-sync-handler::instantiate` takes `stake_registry_code_id` + `service_manager_instantiate` parameters.
- Handler emits an `Instantiate2` for stake-registry with `owner = env.contract.address`.
- Stake-registry instantiate accepts an explicit `owner: Addr` field instead of using `info.sender`.
- Stake-registry then chains the service-manager instantiate as today.

**Quorum-sync path:**
- `mirror-quorum-sync-handler::instantiate` either (a) gets a reference to the service-manager from the operator-sync flow, or (b) instantiates service-manager itself with `admin = env.contract.address`.
- Service-manager instantiate accepts explicit `admin: Addr` instead of `info.sender`.
- CLI passes the EVM source addresses to each handler as today.

### 5b — Owner / admin transfer for rotation

- `mirror/stake-registry::ExecuteMsg::TransferOwnership { new_owner }` (two-step with `AcceptOwnership`).
- `mirror/service-manager::ExecuteMsg::SetAdmin { new_admin }` (same).
- CLI `cli setup mirror` flow updated to use the new chain.

## Phase 7 — Cross-cutting hardening + tests (M-2, L-4, L-5, plus regression coverage)

### 7a — Cross-chain digest format vector test (M-2)

Unit test in `mirror/stake-registry/tests/` and the new `ecdsa/service-manager/tests/` and `bls/service-manager/tests/`:

- Pin `keccak256(envelope) → eip191_hash_message → secp256k1_recover` with a known vector. Reject on output mismatch.
- For BLS: pin DST + `hash_to_g2` + pairing-equality with a known vector.

These are the canary tests that catch any future deviation from the EVM signing contract.

### 7b — Snapshot-correctness regression tests (H-2)

Per the audit's suggested test:
- Register operator A at block N, weight 10.
- Advance to block N+5; register B, weight 10.
- Sign envelope with `reference_block = N` listing both A and B.
- Assert: B's weight does **NOT** contribute. Total signed weight = 10. Quorum 2/3 of 10 fails.

### 7c — Deploy-flow integration test (C-5)

End-to-end multitest:
1. CLI signer instantiates `mirror-operator-sync-handler`.
2. Handler instantiate-2's stake-registry with handler-as-owner.
3. Handler emits a signed envelope for `BatchSetOperatorDetails`.
4. Stake-registry accepts the call; assert `OPERATOR_REGISTERED` updated.
5. Repeat the negative case: a direct call from the CLI signer → `Unauthorized`.

### 7d — Migrate entrypoints (L-4)

Add `#[entry_point] pub fn migrate(...)` stubs to every contract. Default body: `set_contract_version` + `Response::default()`. Real migration logic deferred but the entrypoint is reserved.

### 7e — Operator-set boundary tests

- Empty signers list → reject.
- Duplicate signing key → reject (sorted-signers check).
- Signer not in operator set → reject.
- Operator with weight 0 → does not contribute.
- Quorum exactly at threshold → accept.
- Quorum one weight short → reject.
